# GPT 问答、Codex 任务与中英翻译

本次在已有 V1.1 的学习记录、命令面板与界面上增补功能；原有报告、笔记、学习记录和纠错继续保留。本次用户明确选择沿用 ChatGPT 订阅、不增加 API 费用。

## 如何使用

1. 在文献库导入 arXiv 或自己的 PDF，导入后立即能读原文。
2. 阅读器顶部打开 **Codex 工作台**：查看本机登录状态，点击“验证 Codex 连接”、生成/更新研究报告。任务有真实进度、完成/失败状态与取消按钮。研究报告通过已有 publisher 验证后发布，页面自动读取。
3. 阅读时用**离线划词翻译**（选中英文即出译文，见 README）。早期的整页「中文译文 / 中英对照」阅读模式和 Codex 逐页 / 整篇翻译任务都已移除；旧版本留下的 `translations/` 文件夹不会被删除或覆盖。
4. “带着上下文提问”默认使用 ChatGPT，也保留原有其他站点。复制上下文，在你的 ChatGPT 会话粘贴提问；把得到的回答粘回 **把回答保存回这篇论文**。问答与论文版本、页码、上下文一起保存到 `qa.jsonl`。记录明确标为“用户粘贴”，不会伪称自动获取或经过独立验证的 GPT 回答。

## 费用与连接

没有 OpenAI API Key，没有后端 GPT API 调用，也不读取聊天 Cookie。Codex CLI 使用本机 **ChatGPT 登录**，任务会消耗已有 **Codex 订阅额度**，并非无限免费；额度用尽时会显示失败信息。尚未登录时，在终端运行 `codex login` 并选择 ChatGPT，之后重试。

首次调用可能需要约一分钟或更久，取决于网络、篇幅、排队和模型。当前网络对 WebSocket 有超时，因此本集成使用官方支持的 HTTP 传输设置，只针对本次进程，不修改全局 Codex 配置。

## 实现与数据保护

- `backend/app/workspace.py` 只接收 check / analyze / prepare_sources 固定任务，不接收任意系统命令、磁盘路径、模型提示词或可执行脚本。
- 任务串行执行；`codex exec` 使用临时隔离目录、只读沙箱、禁用 shell 和 apps、结构化输出，沿用本机 ChatGPT 登录，不继承 API Key，不读取论文外的个人文件。模型拿到的是后端明确选出的原文和必要上下文。
- 报告在隔离任务输出目录生成，再通过原有来源与 Schema 验证。模型输出不能直接写正式数据目录。笔记、学习记录、纠错、问答和译文不进入报告替换集合。
- 翻译核对 paper_id、version、PDF SHA-256、页文本 SHA-256 和完整 segment ID，缓存与源文件不一致时不返回旧译文。整页一起翻译，避免 PDF 字形块把上下标切成独立“段落”。
- 每个成功的真实 Codex 任务记录引擎、认证方式、完成时间、输出哈希及 CLI 可提供的 usage。回执证明执行发生，不等同翻译语义被专家审核。
- 任务记录与暂存文件在 Git 忽略的 `.runtime/jobs/`。问答与译文跟随 papers/ 备份；不会自动 Git push。中途重启会把不再运行的旧任务标失败，可重试。
- Markdown 不执行原始 HTML；KaTeX 禁用 trust；远程 Markdown 图片显示为说明文字，避免源内容自动触发外站资源请求。

## 验证方式

后端：`pytest` 覆盖问答持久化、报告重新生成保留问答/笔记/学习记录、翻译缓存校验、错误段落拒绝、固定任务输入和来源哈希。

浏览器：保留原导入/精读/Study 流程，并增加 ChatGPT 问答保存重读、中英模式切换、自动翻译任务和错误恢复。使用测试替身的译文明确带“测试夹具”，不用于声称真实翻译成功。

真实订阅调用的验证在本机用自己导入的论文进行：复制到隔离目录，通过实际 CLI 生成完整报告并核验人工文件不变，不会覆盖你的正式版本。

参考：[Codex 非交互模式](https://learn.chatgpt.com/docs/non-interactive-mode)、[官方配置示例](https://learn.chatgpt.com/docs/config-file/config-sample)。
