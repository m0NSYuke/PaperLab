# Technical decisions

## V1.1 (2026-10-21) — reading-to-understanding layer and Claude-style UI

12. **Visual style after anthropic.com**. Warm ivory/slate palette and clay accent taken from anthropic.com's published CSS tokens (`#faf9f5`, `#141413`, `#d97757`, `#c6613f`, olive `#788c5d`, sky `#6a9bcc`). Anthropic's own typefaces are proprietary, so open substitutes are bundled locally via @fontsource (offline-safe): Source Serif 4 (optical sizes) + Noto Serif SC simplified subset for headings and report prose, Inter for interface chrome, Cambria Math as the fallback for glyphs like ₀. Report text is set in serif at 16.5px/1.85, like a typeset paper; UI sizes rose from 8–12px to 12.5–15px. The brand mark is our own (page + spark); no Anthropic logo or name is used as branding. Class names were kept so the existing tests and structure still hold.
13. **Study layer is human-owned**. New `papers/ID/vN/study.json` (passes, checked reading stops, self-test attempts and verdicts, the reader's own value judgment, ideas). Same durability rules as notes: etag optimistic concurrency (409 on stale writes), prior versions to `.history/`, never touched by report publishing. Autosaves with a 600 ms debounce and a keepalive flush on unmount. `/api/study/overview` aggregates per-paper summaries and all ideas for the library.
14. **Report schema 1.1** adds optional `reading_guide` (first_pass / must_read page stops, page-range validated) and `self_test` (recall / understand / transfer, answers with citations validated like claims). 1.0 reports remain valid without migration.
15. **Research-method choices** (why these features): three-pass reading (S. Keshav; Li Mu's paper-reading order) → reading route; Feynman-style self-explanation before revealing answers → self-test; Li Mu's value = novelty × effectiveness × problem size, plus Levine's "where does the data / bottleneck come from" and Hamming's "important problem" prompts → research judgment that only the human fills; Schulman's research notebook and reviewer-style critique → idea notebook aggregated across papers.
16. **No live AI in the web app (still)**. Considered a local `claude -p --tools ""` bridge for instant questions. On this machine Claude Code is routed through a third-party gateway and headless mode reported "Not logged in", so it was not built. The ask dialog instead prepares context for Claude / ChatGPT / Kimi / DeepSeek with learning modes (Socratic questioning, Feynman check). Revisit if a reliable local headless path exists; any bridge must disable all tools because paper text is untrusted.
17. **Keyboard-first interaction**. Ctrl/⌘+K command palette (tabs, page N, reading-route stops, concepts, status, open paper, import, theme); in the reader `1–7` tabs, `[` `]` pages, `/` search, `A` ask — ignored while typing or when a dialog is open.
18. **Agent parity**. `.claude/skills/paper/SKILL.md` and `CLAUDE.md` point Claude Code at the same canonical `.agents/skills/paper` workflow, so `/paper` (Claude Code) and `$paper` (Codex) produce the same report format.

## GPT / Codex workspace integration (2026-10-21)

19. **Subscription-backed fixed Codex tasks** (supersedes the no-bridge portions of 1 and 16). The user authorized web integration and chose the existing ChatGPT subscription instead of API billing. FastAPI may launch only fixed check/analyze/translate tasks through the local ChatGPT-authenticated Codex CLI. Each run ignores user config, disables shell/apps, uses an isolated read-only workspace and constrained JSON output, and records a receipt. An ephemeral HTTP provider avoids the local websocket timeout without editing global Codex configuration. No API key is requested or passed. Subscription limits still apply.
20. **Human-mediated ChatGPT Q&A**. The reader prepares source/page/question context, links to ChatGPT and stores pasted answers in qa.jsonl with user_pasted provenance. This preserves the user's chosen subscription workflow without claiming embedded ChatGPT access. Reports never replace saved Q&A, notes, corrections or Study records.
21. **Source-bound page translations** (superseded by 39). Chinese and bilingual views reflow complete extracted page text; the unchanged PDF is always available for layout, figures and mathematical notation. Missing pages start a translation task, valid caches can be read offline, and source/PDF hashes invalidate stale caches. Sparse text layers are disclosed rather than filled with invented OCR. Translation tasks exclusively own their cache; report publishing does not replace it.
22. **Per-machine GPT-authored papers.** A user may keep certain papers' analysis with GPT. Their IDs are listed in `PAPERLAB_GPT_AUTHORED` (`.env.local`); web Codex analysis and X-Ray jobs refuse to rewrite them, and the UI reads the list from `/api/automation/status`. Empty by default.

23. **RAP source-first adapter (2026-10-21)**. Integrate the installed read-arxiv-paper method as a project `$rap` skill plus the shared `$paper` helper and web report job. Reuse pinned arXiv endpoints and safe extraction, statically resolve LaTeX dependencies (including compiled .bbl), and expose ambiguity, missing files and truncation. Source prepares notation/structure; PDF remains authoritative for page citations and publication checks. Keep canonical reports and human records in existing paths instead of nanochat's cache/summary destinations; no global skill or AI billing changes. Source preparation does not regenerate reports or alter explicit GPT/Codex authorship assignments.

24. **Report-first learning flow (2026-10-21)**. The user wants detailed explanations before external GPT questions. Add a continuous guide, local lookup over saved explanations, report/PDF focus layouts and paragraph/formula question seeds. Keep the original 1–7 tab shortcuts; 8 opens the guide. New report generation requests schema 1.2 with optional `tutorial` (prerequisites, walkthrough, worked examples, FAQ); preserve 1.0/1.1 compatibility. Teaching examples must be labeled, unknown source details disclosed, and tutorial citations validated by the existing PDF publisher. This changes the generation contract, not existing scientific content or decision 22's authorship. `questions.jsonl` stores human-owned append-only question snapshots with source page, report revision and reversible resolved state, independent of reports and saved answers. Copying unresolved questions batches external Q&A; the user still pastes and sends in ChatGPT and may return the answer. No API charges, automatic chat sending or automatic answer retrieval are introduced.

25. **Complete project-local Nature Skills library (2026-10-21)**. The user explicitly requested all open-source Nature Skills and automatic relevant selection for later reading/writing. Install all 23 top-level packages from Yuan1z0825/nature-skills at commit c6ae86c742705fd968b13c79db1a8518a84089d4: 22 task skills and nature-shared, preserving the entire 808-file tree and per-material notices. Use the official Codex skill-installer to stage, validate against Git blob hashes and Codex frontmatter rules, then copy without replacing existing skills. Keep original upstream files unchanged, a full hash manifest and Apache license copy. AGENTS.md and docs/NATURE_SKILLS.md route natural requests; the existing paper skill consults X-Ray while retaining pinned sources, report schema/publisher and authorship rules. researchwrite keeps its upstream trigger despite the nature-proposal-writer folder name; nature-shared keeps implicit invocation disabled. No global install/hooks, recurring task, external transmission, paid API setup or bulk dependency changes; optional per-skill runtime/services are selected only for a relevant authorized task. Existing webpage fixed jobs keep their bounded runtime rather than gaining arbitrary installed-script access.

26. **User-initiated research workspace (2026-10-21)**. The user then explicitly requested activation and a website redesign. Extend the original reader scope with Library, Studio, Skills and Outputs. A fixed 22-task registry reads the pinned installation; seven text-only workflows use the existing subscription CLI with tools disabled, while fifteen workflows requiring network/tool execution produce an explicitly prepared handoff packet for the full native Codex environment. A prepared packet is not a completed PPT, review, search or translation. Load only hash-verified entrypoints, manifests, core files and applicable writing fragments; preserve a per-job guidance snapshot and receipt. Text-only reading discloses native PDF extraction without visual inspection. Validate exact selected-paper quotes and the pinned PDF hash before saving. New research artifacts live separately under research-outputs/job_ID; mutable drafts use etags and historical copies. Research models remain in models.py with exported schemas. Task URLs restore queued/running/completed jobs after refresh, and navigation/unload protects unsaved edits. No canonical reports or human records are replaced; decision 22 remains enforced at both web report and X-Ray submission. User-supplied material is required for writing; missing evidence must remain explicit. No extra API, arbitrary command endpoint, scheduler or remote publication is introduced.

## Zotero-style reader and offline selection translation (2026-10-22)

27. **Reader chrome collapses to one bar.** The user asked for more room for the paper, Zotero-like. Inside a paper the global header is hidden; title, page/zoom/language controls (portaled from PdfPane so viewer state stays local), search, view modes, ask, Codex workbench, a More menu (pending questions, X-Ray, Studio, metadata, reading status) and panel toggles share one 48 px bar. The separate view-mode row, PDF toolbar, search row, PDF footer and bottom status bar are removed; reading progress is a 2 px line. Search is a floating find bar (Ctrl F or /), notices are transient toasts. The outline moves into a collapsible left sidebar that also lists the reading route; the explanation pane collapses from the bar. Focus mode (F) hides everything but the paper and reveals the bar at the top edge. On a 1440×900 screen the PDF went from ~580 px to ~850 px tall. All earlier labels the tests rely on (论文目录, 适宽, 查找, 论文阅读语言, Codex 工作台, a.brand) are kept.
28. **Motion with a purpose.** Panes slide by interpolating grid tracks (disabled while dragging), sidebars animate width, report tabs use a sliding indicator and fade-in content, menus and cards pop from their anchor, library sections and cards stagger in. Durations stay 150–360 ms with one ease-out curve; `prefers-reduced-motion` turns all of it off.

29. **Offline selection translation, no quota.** The user declined Codex for sentence translation (it spends subscription quota) and asked for a high-quality offline model on drive D. Words and short terms: ECDICT (MIT, 770k entries, phonetics, exam tags) indexed into SQLite by `scripts/build_dictionary.py`, plus a curated 213-entry AI/robotics glossary (`backend/app/data/academic_terms.json`) that outranks general dictionary senses (ablation → 消融实验, not 切除); personal terms saved from the card go to `knowledge/glossary/user-terms.json` and override built-ins. Sentences: Tencent Hy-MT2-7B (Apache-2.0, translation-specialised, Q4_K_M 4.6 GB fits the RTX 4060's 8 GB) served by llama.cpp's llama-server. The backend starts it on first use (127.0.0.1 only, random per-launch API key, no web UI), stops it after 15 idle minutes or on exit, injects matching glossary terms with the model card's terminology prompt, uses the card's decoding settings, and caches results in `.runtime/mt-cache.sqlite`. PDF ligatures and hyphenated line breaks are repaired before lookup. Paths live in the git-ignored `.env.local` (see `.env.example`). Browser tests point the model path at a missing file so they never load the GPU model. Whole-page translation stays with the existing Codex job.

## Readable reports and reader polish (2026-10-22)

30. **Readable notation is enforced at publication.** The user asked that every formula and number in a report be directly readable. `publish_report` now rejects reports whose prose contains ASCII `^`/`_` scripts, LaTeX commands outside `$...$`, or decimals without a leading zero, and lists the offending fields (PDF quotes, LaTeX and identifiers are exempt). The rule is written into AGENTS.md and the paper skill's report-spec/quality rubric. Existing reports were not regenerated; the reader converts their legacy plain-text maths (`A^τ`, `W_cls^l`, `.25`) for display only, without altering report files.
31. **Report outline rail and selection-card placement.** The report pane gets a Notion-style outline (one bar per heading, titles on hover, always open in the wide 讲解 view). The selection translator never covers the selection: it is placed above/below or beside it, can be dragged, docked to the side opposite the selection (resizable, D toggles), keeps a 30-item history and can append an excerpt to the paper's notes with the usual etag check.
32. **Conversational, concrete report prose.** The user asked for GPT-style explanations that are less rigid, more vivid and more professional. `.agents/skills/paper/references/writing-style.md` (referenced from the paper skill, report-spec and quality rubric) asks for answer-first units, an analogy / walked-through input / hand-checkable number per mechanism, precise bilingual terminology, short paragraphs, tables for comparisons and at most two callouts per unit. Analogies are labelled and never add facts. The reader renders GitHub-style callouts (`> [!INTUITION]`, `[!ANALOGY]`, `[!KEY]`, `[!PITFALL]`, `[!NOTE]`) as labelled boxes. Existing reports change only when regenerated through the publisher.

## Phone and iPad reading (2026-10-22)

Selection translation also listens to `selectionchange` on touch input (coarse pointer or a non-mouse `pointerdown`), debounced 450 ms, because long-press selection and handle drags fire no `mouseup`; the card keeps 30 px from a touch selection so it clears the drag handles. Below 640 px the docked translator becomes a bottom sheet; touch controls are enlarged and touch inputs use 16 px so iOS does not zoom on focus. The reader uses `100dvh`, the narrow toolbar's right group scrolls sideways, and its empty PDF-control row is hidden in report view. At the user's request (same Wi-Fi), `Start-PaperLab-LAN.cmd` runs `scripts/start.ps1 -Lan`: uvicorn binds 0.0.0.0 and `PAPERLAB_LAN_TOKEN` enables a guard in `create_app`. Requests addressed to localhost behave as before. Any other Host must come from a private-range client and carry the key, given once as `?key=` (answered with a 303 that sets an HttpOnly, SameSite=Strict cookie for 180 days and strips the key) and then sent as the cookie; the cookie is bound to the LAN address, so a DNS-rebinding page under another name never has it, and the existing Origin check still blocks cross-site writes. The key lives in ignored `.runtime/lan-token`, is reused across restarts, and is revoked by deleting that file. The launcher prints links only for adapters with a default gateway and warns when Windows marks the Wi-Fi as Public. The default launcher stays local-only, switching modes requires a stop first, and nothing changes firewall settings. `index.html` is served with `Cache-Control: no-cache` so phones pick up rebuilt assets.

## PDF highlights and annotations (2026-10-22)

36. **Highlights live beside the notes, one item at a time.** Selecting text in the English PDF shows a colour row in the selection card (yellow, green, blue, pink, purple); with translation switched off the same card appears with only highlighting and 提问. A highlight stores its text, colour, optional note and per-line rectangles as fractions of each page (zoom- and screen-independent) in the human-owned `papers/<id>/<version>/highlights.json`; report regeneration never touches it. The API adds, patches and deletes single items under the data lock (no whole-file etag), so a phone and a desktop marking the same paper cannot overwrite each other; deletions keep a copy in `.history/`. Highlights are painted under the PDF.js text layer (re-painted after every page render) so text over them stays selectable; a click or tap on one opens an editor for colour, note, 记笔记 (appends quote, page and note under the notes' 「划词摘录」, sharing the translator's etag-checked append) and delete. On phones the editor is a bottom sheet. The notes tab lists all highlights by page and jumps to them. Highlights apply to the original PDF only, not the translated page or report text.


## Paper data outside the app folder (2026-10-23)

37. **Paper data can live outside the app folder.** `backend/app/paths.py` resolves the data root: `PAPERLAB_ROOT` (environment only, for isolated test workspaces), then `PAPERLAB_DATA_DIR` from the environment or `.env.local`, otherwise the app folder, where all paper folders are git-ignored. `papers/`, `local-assets/`, `concepts/`, `knowledge/`, `research-outputs/` and the data `.runtime/` (jobs, data lock, translation cache) live there; frontend, docs, skills, `.env.local`, LAN token and server logs stay with the app. `create_app(root)` with an explicit root treats it as both, so tests and e2e workspaces are unchanged. Linked data paths remain forbidden.

## Public repository (2026-10-24)

38. **The repository ships the platform, not the maintainer's reading.** Papers, reports, notes, study records, screenshots of read papers, paper-specific export scripts and run logs stay in the user's data directory or in git-ignored files. Decisions tied to a specific paper go to `docs/DECISIONS.local.md`. Third-party Nature Skills are installed from their pinned upstream commit by `scripts/install-nature-skills.py` (hash-checked against `docs/nature-skills-installation.json`) instead of being vendored. Machine-specific paths (data directory, translation model, dictionary, display name, GPT-authored papers) come from `.env.local` / `frontend/.env.local` with neutral defaults.

39. **Selection translation only; Codex page translation removed.** The reader lost its Chinese / bilingual page views when offline selection translation (decision on Hy-MT2 + ECDICT) replaced them, which left the Codex `translate_page` / `translate_all` jobs writing a cache nothing displayed. Both jobs, the `/reading/{page}` endpoint and the unused `TranslatedPage` view are removed, so Codex jobs are now check / analyze / prepare_sources. Existing `translations/` folders on disk are left untouched and stay protected from report regeneration.

## Reading chain in reports (2026-10-25)

40. **Reports follow one reading chain, macro before micro, scaled by depth.** Schema 1.3 adds `triage` (depth 精读 / 选读 / 略读, who chose it, the user's one-line context verbatim, problem, core change, headline result, cost, credibility, rationale, focus, supporting claim IDs), `deltas` (component vs prior practice, evidence, load-bearing), `evidence_audit` (claim → experiments, strength, fairness, missing experiment), `comparisons` (cross-paper tables) and an equation `priority` (derive / understand / skip). Markdown and the reader render triage first, then problem, deltas and comparisons, then mechanism and maths, then experiments with the audit. Full derivations are always written and shown collapsed so the reader can derive first. The triage is a recommendation; the reader's verdict stays in study.json. Accuracy is enforced at publish, not only requested: references must resolve to existing claims and experiments, load-bearing judgments need evidence, and every multi-digit or decimal number in the summary layers must already appear in the report's claims, experiments or verified quotes. Comparison rows are `this_paper` (own PDF), `local_report` (another library paper's published report, quotes verified against that paper's pages) or `unverified` (qualitative, no digits), so no table cell can carry a number from memory. 1.0–1.2 reports stay valid and are not migrated.

## Research lines, reading status and backups (2026-10-26)

- Papers are grouped primarily by research line (the idea or direction they serve, in reading order with a role per paper), stored as hand-edited `<data>/lines.json` and served read-only by `/api/lines`. Topics stay as technical tags; a paper may sit in several lines.
- Opening a paper still marks it 阅读中; 已完成 is set explicitly from the end of step 3 (自测与思考), so library counts reflect real progress.
- The server backs up user-written data as rotating zips outside the data drive (`PAPERLAB_BACKUP_DIR`, default `~/PaperLab-backups`, keep 10, skip when unchanged). Re-downloadable arXiv PDFs and LaTeX are excluded; imported local PDFs are included. The backup thread starts with the server, never on import.
- Concept cards are linked from each report's `concept_links` and shown first in the 精读 background chapter by their display names.

## Library knowledge search and graph (2026-10-26)

- Borrowed from paperwise (HJCheng0602/paperwise): a library-wide knowledge base, a paper–concept graph and related-paper context while writing reports. Not borrowed: whole-paper bilingual PDF translation (removed earlier by choice) and per-section independent model calls (PaperLab reports are written in one pass by the agent).
- Search is local BM25 over report prose, claims (with PDF page), equations, tutorial units, notes, 随记 and concept cards; Latin words plus CJK character bigrams, no embeddings or model calls. The index rebuilds only when a source file's mtime or size changes (backend/app/knowledge.py).
- The graph uses only what the library states (concept_links, related_papers matched to library titles, local_report comparison rows, lines.json) plus TF-IDF report similarity. Concept and similarity edges are off by default because hub concepts collapse the layout.
- `paper.py related ID --version vN` lists the closest library papers for the paper skill's cross-paper comparison step; it falls back to the paper's first pages before a report exists.
